# usage-overview · wireframe 计划

## 目的
在修改生产 dashboard 前，用线框验证使用量总览的信息层级、五大数据态与窄视口可读性，
降低直接改生产 UI 的返工风险（OpenSpec: improve-usage-overview-analytics，能力 usage-overview-prototype）。

## 受众
- 评审者：Felix（开发者，读中文）
- 参照实现方：后续 4.x 生产面板任务的执行者

## 范围
包含：
- 单页面「使用量总览」：时间范围、消费指标、消费趋势、provider/model 消费排行、
  项目费用排行、效率排行、解释型建议卡片
- 5 个数据态独立文件：有数据 / 无数据 / 真实延迟不可用 / 样本不足 / 建议不可用
- 桌面与 <800px 窄视口两套断点表现
不包含：
- 高保真视觉（颜色、字阶、真实数据接入）
- 生产代码、生产路由、生产数据库的任何改动
- 复杂图表交互（tooltip、堆叠面积图、缩放）——记入 OpenSpec 1.3 未采纳清单

## 已定决策（来自深挖）
1. 建议卡片：纵向堆叠（结论行 → 依据/样本/时间范围/置信度）
2. 数据态：独立文件，一屏一文件（01–05）
3. 趋势：灰阶内联 SVG 折线占位，无交互
4. 壳对齐成品（评审修正）：range 四档在 tablist 之前 + 四标签（总览/统计/趋势/供应商），data-tab-panel 切换，不做单页长滚动
5. 总览面板主次：P0 五指标（auto-fit 网格同成品 .kuma-overview）→ P1 建议卡片（纵向、弱边框、结论行突出）→ P2 排行摘要（3列×3列小表，完整口径在统计标签）
6. 排行摘要桌面三列并排、<800px 上下堆叠；视觉降噪：去区块满边框，层级只靠字号/留白/灰度三级

|---|---|---|---|

## 交付形态
- 一屏一文件：`current/screens/<ID>.html`，灰阶 + 内联 SVG，仅 background/foreground/border/muted 四 token
- 每块带 `data-wireframe-block` + `data-priority`；可修改元素 `id` = 语义字典全路径
- 占位文案中文 12–20 字，禁 lorem ipsum；页面标注「示例数据，未接入生产」
- 默认暗色 + 中文，页内可切换（线框级）

## 主题与语言
主题 token 只取自根目录 `THEMES.md` 四个基础色；界面默认 zh-CN。

## 成功标准
1. 打开 01 即可判断各区块相对层级与决策链（钱→哪里花→谁快→怎么办）
2. 5 态各自能表达「暂无数据/样本不足/无法计算」，不出现误导性 0 值或最佳结论
3. <800px 视口下核心指标、排行、建议依据全部可读，宽表可横向滚动
4. 桌面（≥800px）与窄视口预览各跑一遍并确认

## 评审结论（2026-09-22 第一轮）
- 「太复杂、视觉混乱无主次」→ 采纳：降噪（去满边框）+ 总览面板内 P0/P1/P2 三级主次（已定决策 5–6）
- 「与本仓库成品页不一致」→ 采纳：壳对齐 generateDashboardHTML（range 前置于 tablist、四标签、kuma-overview auto-fit 网格、kuma-overview-notice 提示条）；趋势挪入趋势标签，统计全列在统计标签
- 未采纳候选（待 OpenSpec 1.3 确认入未采纳清单）：tooltip 悬浮数值、堆叠面积图、图表缩放/拖拽
- 本轮修改不升版本，回滚目标 v1

## 未决问题
- 无（建议卡片布局已由评审者定为纵向堆叠；其余均有 spec 依据）

## 任务编排节（只写切分理由）
骨架→tokens→主态→逐状态→自检→字典收尾：先立结构再填内容，每个数据态独立成任务，
便于逐个勾选与回滚；字典登记与徽标标注放最后，因为它们依赖 HTML id 已写定。
