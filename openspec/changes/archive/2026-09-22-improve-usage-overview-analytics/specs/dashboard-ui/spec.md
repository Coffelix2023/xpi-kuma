## MODIFIED Requirements

### Requirement: 使用量总览展示

系统 SHALL 在使用量总览标签页展示本期用量，包含本周期花费、token 总量、请求次数、覆盖项目数和可计算的缓存命中率，并随所选时间范围刷新。总览 SHALL 提供消费结构、provider/model 消费排行、项目费用排行、效率排行和解释型建议的入口或区域。效率与建议无数据时 MUST 保留基础总览并显示明确空态。面板视觉 SHALL 采用 shadcn base 组件规范的 CSS 移植：只用仓库既有 CSS token 实现，MUST NOT 引入 React、构建步骤或任何外部资源。

#### Scenario: 展示扩展后的概览
- **WHEN** 用户打开主面板且所选时间范围内有使用量记录
- **THEN** 标签页显示本期花费、token 总量、请求次数、覆盖项目数、缓存命中率，以及消费排行和项目费用排行

#### Scenario: 展示四项概览
- **WHEN** 用户打开主面板且所选时间范围内有使用量记录
- **THEN** 标签页显示本期花费、token 总量、请求次数与覆盖项目数，数值与使用量统计一致

#### Scenario: 展示效率与建议
- **WHEN** 时间范围内存在满足样本阈值的真实调用延迟数据
- **THEN** 总览显示效率排行和带样本数、时间范围、依据与置信度的只读建议

#### Scenario: 效率数据不可用
- **WHEN** 时间范围内没有可靠真实调用延迟或样本不足
- **THEN** 总览保留基础统计，并将效率排行和建议标记为暂无数据或样本不足，不使用 probe 或估算值替代

#### Scenario: 切换时间范围刷新概览
- **WHEN** 用户从“24小时”切换到“7天”
- **THEN** 所有概览、排行、项目归因、效率和建议均按新范围重新计算

#### Scenario: 无记录时
- **WHEN** 所选时间范围内没有任何使用量记录
- **THEN** 概览显示零值或暂无数据，并引导用户查看产生数据的路径
### Requirement: 使用量统计展示
系统 SHALL 在使用量统计标签页展示按 provider/model 分组的真实使用量，并提供按费用、tokens、请求数排序的消费排行；排行 SHALL 展示费用占比、单请求成本和可计算的缓存命中率，默认限制首屏数量并将其余组合汇总或折叠。

#### Scenario: 显示消费排行
- **WHEN** 用户选择任一时间范围且存在多个 provider/model 组合
- **THEN** 统计区域显示按费用排序的主要组合，并为每行提供费用、费用占比、tokens、请求数和单请求成本

#### Scenario: 显示24小时统计
- **WHEN** 用户选择“24小时”时间范围且数据库中有相关记录
- **THEN** 统计表格显示所有 provider-model 组合的24小时聚合数据

#### Scenario: 切换时间范围
- **WHEN** 用户从“24小时”切换到“7天”
- **THEN** 统计表格、消费排行和趋势图表更新为最近7天的数据

#### Scenario: 空数据时显示
- **WHEN** 用户选择一个没有记录的时间范围
- **THEN** 统计表格显示暂无数据或等价空态，而不是误导性的非零行

#### Scenario: 小样本组合
- **WHEN** 某 provider/model 组合只有少量请求
- **THEN** 该组合仍可出现在基础统计中，但不得仅凭少量数据进入最佳效率或解释型建议
