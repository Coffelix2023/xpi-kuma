## MODIFIED Requirements

### Requirement: 通过命令打开监控面板

系统 SHALL 提供 `/xpi-kuma` 命令，执行后启动或复用仅监听本机回环地址的监控 Web 服务，并使用系统默认浏览器打开监控面板。

#### Scenario: 成功打开面板

- **WHEN** 用户在已初始化的 Pi 会话中执行 `/xpi-kuma` 命令
- **THEN** 系统启动或复用当前会话的监控 Web 服务，并使用系统默认浏览器打开带有本次服务访问凭据的本机 URL

#### Scenario: 浏览器无法自动打开

- **WHEN** Web 服务已成功启动，但系统默认浏览器无法自动打开
- **THEN** 系统保持服务运行，并通过 Pi 通知显示可复制的本机访问 URL

#### Scenario: 重复执行命令

- **WHEN** 用户在同一 Pi 会话中重复执行 `/xpi-kuma` 命令
- **THEN** 系统复用已有 Web 服务和访问凭据，不创建重复监听器，并再次打开或显示同一面板 URL

#### Scenario: 无配置供应商时提示

- **WHEN** 用户执行 `/xpi-kuma` 但配置文件中无任何供应商
- **THEN** 浏览器面板显示提示信息："未配置任何供应商，请编辑 .pi/xpi-kuma/config.yaml"

### Requirement: 实时数据更新

系统 SHALL 支持面板数据的手动刷新和自动轮询刷新；探测完成或新的使用量记录写入后，面板 SHALL 在下一次成功刷新时展示最新数据，且同一页面不得并发发起重复的自动刷新请求。

#### Scenario: 手动刷新全部数据

- **WHEN** 用户点击面板上的"全部刷新"按钮
- **THEN** 系统对所有配置供应商执行探测，并重新查询使用量统计，更新面板所有区域

#### Scenario: 后台数据更新

- **WHEN** Pi 会话中的新 LLM 调用触发 `message_end` 并成功记录使用量，且面板页面处于可见状态
- **THEN** 面板在不超过5秒的下一次成功轮询后包含该新记录

#### Scenario: 页面不可见时暂停轮询

- **WHEN** 面板所在浏览器标签页进入不可见状态
- **THEN** 系统暂停自动轮询，并在页面恢复可见后立即执行一次刷新再恢复轮询

#### Scenario: 自动刷新失败

- **WHEN** 自动刷新请求因服务关闭或临时错误失败
- **THEN** 面板显示可理解的连接错误，保留当前已渲染数据，且不产生无界重试或并发请求

### Requirement: 响应式布局

系统 SHALL 确保面板在不同浏览器视口尺寸下保持可用性，供应商卡片自动换行，表格可横向滚动，图表自适应可用宽度。

#### Scenario: 小窗口时卡片自动换行

- **WHEN** 浏览器视口宽度小于800px 且有4个供应商卡片
- **THEN** 卡片网格减少列数并保持每个卡片内容可读，统计表格不会撑破页面布局

## ADDED Requirements

### Requirement: 本机服务访问控制

系统 MUST 仅在 IPv4 回环地址 `127.0.0.1` 上监听随机可用端口，并 MUST 使用每次服务启动时生成的高熵随机访问凭据保护所有返回监控数据或触发探测的接口。系统 MUST NOT 将供应商 API Key、访问凭据或其他密钥写入日志、页面正文或错误响应。

#### Scenario: 非本机连接不可达

- **WHEN** 远端主机尝试通过设备的局域网地址访问监控端口
- **THEN** 连接不可达，因为服务没有监听非回环网络接口

#### Scenario: 未授权数据请求

- **WHEN** 请求未携带当前服务的有效访问凭据，或请求的 Host 与当前监听地址不匹配
- **THEN** 系统拒绝请求且不返回任何监控数据

#### Scenario: 未授权探测请求

- **WHEN** 请求尝试触发单个或全部供应商探测，但缺少有效访问凭据或来自不匹配的 Origin
- **THEN** 系统拒绝请求且不向任何供应商发送探测

#### Scenario: 浏览器地址不泄露密钥

- **WHEN** 系统构造并打开监控面板 URL
- **THEN** 访问凭据不得出现在会发送到 HTTP 服务、访问日志或第三方资源 Referer 的 URL 查询参数中

### Requirement: Web 服务生命周期

系统 SHALL 将监控 Web 服务绑定到当前 Pi 扩展会话的生命周期，并 SHALL 在会话关闭时停止接受新请求、取消后续页面刷新能力并释放监听端口。

#### Scenario: 会话关闭释放服务

- **WHEN** Pi 触发 `session_shutdown`，包括退出、reload、新建、恢复或 fork 会话
- **THEN** 系统关闭当前监控 Web 服务并释放端口，原浏览器页面的后续请求不再成功

#### Scenario: 服务关闭不阻塞 Pi

- **WHEN** `session_shutdown` 发生且浏览器仍保持页面打开
- **THEN** 系统在有限时间内完成服务关闭，不等待浏览器主动断开，也不阻止 Pi 继续关闭或切换会话

#### Scenario: 新会话重新打开

- **WHEN** Pi 已完成会话切换并再次执行 `/xpi-kuma`
- **THEN** 系统为新扩展会话启动新的本机 Web 服务和访问凭据，旧凭据不能访问新服务
