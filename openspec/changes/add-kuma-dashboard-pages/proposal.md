## Why

`.pi/prototype-design/kuma-dashboard` 已把监控面板定稿为 4 个 hifi 页面（主面板、零数据引导态、供应商账户、配置体检），但成品只有一张单页 Web 面板：它只回答"哪个供应商还活着、花了多少钱"，既不回答"钱花在哪个项目上"，也不告诉用户"余额还剩多少""配置哪里写错了"。原型定稿与成品之间存在一个完整的页面级缺口，本次把缺口补齐。

## What Changes

- **多页面与路由**：把单页面板扩展为 4 个页面，各自独立 URL 与页头互链——`/`（主面板）、`/empty`（零数据引导态）、`/accounts`（供应商账户）、`/settings`（配置体检）。四页共用同一套服务、访问凭据、主题与语言偏好。
- **主面板新增区块**：按原型补上花费概览（本期花费 / token 总量 / 请求数 / 覆盖项目数）、用量归因（项目 / 会话 / 供应商·模型三档维度切换 + 明细表）、分区索引轨（Atlas 家族下显示）。现有供应商健康块由首屏主角降为次级块。
- **零数据引导态**：首次运行、无记录、未配供应商时用引导页替代主面板，给出产生数据的三条路径与返回入口。
- **供应商账户页**：新增余额视图，含账户概览（累计充值 / 当前余额）、按余额升序的账户明细表（数据来源、余额、累计充值、最近同步、动作）与空态。余额按三档降级取数：服务商余额接口 → OAuth 授权查询 → 手动填写。
- **配置体检页**：新增只读诊断页，摊开 `config.yaml` 的真实解析结果（生效路径、来源、YAML 解析、修改时间）、逐供应商六项检查（必填字段 / endpoint / model / api_key 环境变量是否设置 / 价格完整性 / 探测配置）、全局与存储项（retention、usage.db 路径与大小、探测默认值、会话 cwd），以及解析失败时的 fail-closed 替代卡。**该页不产生任何写盘操作。**
- **用量归因的数据基础**：`UsageRecord` 新增 `cwd` 与 `sessionId` 采集，数据库加列并提供存量数据迁移策略，归因表据此支持项目与会话两档聚合。
- **横切：主题家族与语言**：落地 `THEMES.md` 的两套家族（Default / Atlas 复古印刷）与中英双语，偏好写 `localStorage` 并在首帧前应用。四页共用同一套偏好键。
- **趋势图去外部依赖**：按原型"整页零外部请求"硬规则，趋势图由 Chart.js CDN 改为页内内联 SVG，同时收紧 CSP。
- **BREAKING**：`usage_records` 表新增列（需迁移）；`.pi/xpi-kuma/config.yaml` 新增余额与授权相关字段（缺失时按默认值降级，不破坏既有配置）；趋势图渲染方式变化（不再加载 Chart.js）。

## Capabilities

### New Capabilities

- `usage-attribution`: 按项目(cwd) / 会话 / 供应商·模型三个维度聚合花费与用量，供主面板归因表消费；包含采集字段与存量数据迁移口径。
- `vendor-accounts`: 供应商余额的获取、来源标记与降级顺序（余额接口 → OAuth 授权 → 手动填写），以及余额与累计充值的持久化与展示口径。
- `config-diagnostics`: 只读的配置与存储体检，摊开解析结果、逐供应商检查项与全局项，解析失败时 fail-closed 展示且绝不写盘。

### Modified Capabilities

- `dashboard-ui`: 面板由单页扩展为四页；主面板新增花费概览与用量归因区块；零数据引导态独立成页；主题家族与中英双语成为面板级能力；趋势图改为内联渲染。现有"通过命令打开监控面板""本机服务访问控制""Web 服务生命周期"三条要求需扩展到多页范围。
- `usage-collection`: 使用量记录新增项目路径与会话标识字段，并在聚合口径中保持向后兼容。

## Impact

**受影响的代码**

- `src/ui/dashboard.ts`：路由表由 4 条扩展为多页 + 多 API；页面与 API 前缀分离；凭据与 Host/Origin 校验对全部页面统一生效。
- `src/ui/dashboard-html.ts`、`dashboard-client.ts`、`dashboard-css.ts`、`theme.ts`：拆为多页 shell 与共享的样式、脚本、主题模块，避免单文件继续膨胀。
- `src/collectors/usage-collector.ts`、`src/index.ts`：`message_end` 采集时补 `cwd` 与 `sessionId`。
- `src/storage/database.ts`：`usage_records` 加列、索引调整、存量行迁移，新增归因聚合与余额查询读写。
- `src/config.ts`、`src/config.example.yaml`：新增余额与授权相关字段的解析与校验（fail-closed）。
- 新增：余额取数模块、OAuth 授权模块、只读体检模块。

**新增的对外接口**

- 页面路由：`/accounts`、`/settings`、`/empty`。
- 数据接口：归因数据、账户与余额数据、体检数据、余额同步触发、OAuth 授权发起与回调。
- 以上全部沿用现有访问控制：仅回环监听、随机 Bearer 凭据、严格 Host 校验、变更类请求校验 Origin。

**依赖与风险**

- 不新增第三方 Web 框架或图表库；余额取数只用 Node 内置 `fetch`，OAuth 只用内置 `http`/`crypto`。
- **OAuth 可行性的未知项**：各供应商是否提供余额查询接口、是否支持 `127.0.0.1` 回调、是否要求预注册客户端，均需在实现前先验证。若某供应商不支持，该行按降级顺序回落到手动填写，而不是伪造数字。
- **迁移风险**：`usage_records` 存量行没有 cwd/sessionId，归因的项目/会话维度对历史数据不可用，只能标注为"未知"并只对新记录生效。
- **密钥纪律**：OAuth token 与手动余额的落盘位置、权限与脱敏口径必须在实现前定死，任何密钥不得进入日志、页面正文或错误响应。
- 影响既有测试面：路由、CSP、凭据校验、数据库 schema 与配置解析的测试都需同步扩展。
