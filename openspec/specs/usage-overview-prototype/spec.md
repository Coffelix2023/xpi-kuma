# usage-overview-prototype Specification

## Purpose

在生产面板实现前提供可评审的使用量总览原型，验证消费结构、项目归因、效率排行、建议卡片、空数据和响应式布局的信息层级，降低直接修改生产 UI 的返工风险。

## Requirements

### Requirement: 原型覆盖总览核心模块

系统 SHALL 提供独立、版本化的总览原型，至少包含时间范围、消费指标、消费趋势、provider/model 消费排行、项目费用排行、效率排行和解释型建议区域。

#### Scenario: 评审核心布局

- **WHEN** 用户打开原型的总览页面
- **THEN** 用户可以在同一页面观察消费结构、项目归因、效率排行和建议模块的相对层级与主要交互入口

### Requirement: 原型覆盖关键数据态

原型 SHALL 覆盖有数据、无数据、延迟数据不可用、样本不足和建议不可用状态，并清晰区分真实统计、缺失数据和推断建议。

#### Scenario: 评审空态与不足态

- **WHEN** 用户查看原型的数据态变体
- **THEN** 每个模块均能表达暂无数据、样本不足或无法计算，而不是展示误导性的零值或最佳结论

### Requirement: 原型支持响应式评审

原型 SHALL 在桌面和窄视口下保持核心指标、排行和建议可读；宽表格可以横向滚动，模块不得因视口变窄而隐藏其语义。

#### Scenario: 评审窄视口

- **WHEN** 用户在小于800px的视口打开原型
- **THEN** 卡片调整布局，排行区域保持可滚动或堆叠，核心指标和建议依据仍然可读

### Requirement: 原型不等同于生产数据实现

原型 SHALL 明确标注示例数据和未接入状态，不得写入生产数据库、修改生产面板路由或暗示推断结果已经接入真实调用。

#### Scenario: 区分原型与生产

- **WHEN** 用户评审原型中的统计或建议
- **THEN** 页面明确说明数据为布局验证用示例，生产实现仍需通过真实 API 与 SQLite 聚合提供
