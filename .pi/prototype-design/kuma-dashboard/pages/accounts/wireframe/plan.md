# plan.md — wireframe (kuma-dashboard / accounts)

> 本阶段唯一需求事实来源。每轮深挖后**覆写本文件**，不新建副本。

## 1. 目的 (Why)

回答「我在这家供应商还剩多少钱」。按供应商列出余额与累计充值，并如实标注每个数字是
**怎么拿到的**（供应商 API / OAuth 授权后查询 / 手工填写）。

## 2. 受众 (Who)

xpi-kuma 开源用户，多为中转服务商用户：余额随时会耗尽，但服务商未必提供查询接口。

## 3. 范围

### 包含

- 账户概览：累计充值 / 当前余额
- 供应商账户列表：供应商·模型 / 数据来源 / 余额 / 累计充值 / 最近同步 / 动作
- 三档数据来源及其状态：`API 查询` / `OAuth 授权`（含授权过期）/ `手动填写`
- 空态：无任何供应商账户信息时的引导

### 不包含

- 供应商余额 API 的**实际探测**（哪些服务商有 `balance` 接口）——实现阶段的事
- OAuth 接入与回调、写盘路径（手动填写要写 config，本轮只画入口）
- 余额告警、低余额提醒（未提出）
- 与 `/xpi-kuma` 命令层的接线

### 数据前提（本轮假设，未验证）

- `config.yaml` 每个供应商将扩出：`balance`（手工值）、`topups[]`（充值记录）、`auth`（OAuth 凭据）
- 累计充值 = `topups[]` 求和，或来自服务商 API 的「已用 + 余额」
- 真实 schema 留到实现阶段定，本原型只固化界面与状态
