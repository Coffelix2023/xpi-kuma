# usage-overview-insights Specification

## Purpose

为本地使用量面板提供可解释的消费结构、效率、缓存收益和项目归因洞察，帮助用户基于真实历史调用判断成本与响应效率，而不自动改变调用配置。

## Requirements

### Requirement: 展示消费结构指标

系统 SHALL 在选定时间范围内展示总费用、总 tokens、请求数、活跃项目数、缓存命中率、费用占比和单请求成本；所有指标 SHALL 使用同一统计口径，缓存命中率分母为零时 MUST 展示未知状态而非伪造百分比。

#### Scenario: 展示有数据的消费结构

- **WHEN** 选定时间范围内存在真实使用量记录
- **THEN** 面板展示总量指标，并为 provider/model 和项目排行提供费用占比、tokens、请求数与单请求成本

#### Scenario: 没有可计算的缓存命中率

- **WHEN** 选定时间范围内 input tokens 与 cache read tokens 的总和为零
- **THEN** 缓存命中率显示为"未知"或等价空值，不显示 0%

### Requirement: 提供受限的效率排行

系统 SHALL 在存在可靠真实调用时间点且样本数达到最低阈值时，按 provider/model 展示成功率、p50/p95 首字延迟和 p50/p95 总响应时间；样本不足或数据缺失的组合 MUST 标注为数据不足，且不得进入最佳效率建议。

#### Scenario: 展示真实效率排行

- **WHEN** 一个 provider/model 组合在时间范围内有至少10条带真实延迟的成功记录
- **THEN** 面板展示该组合的样本数、成功率、p50/p95 首字延迟和 p50/p95 总响应时间

#### Scenario: 延迟数据不可得

- **WHEN** 历史记录没有可靠的请求开始、首字或完成时间
- **THEN** 面板显示暂无真实效率数据，不使用相邻记录、probe 记录或其他估算值替代

### Requirement: 生成解释型建议

系统 SHALL 提供成本、效率和缓存三个维度的只读建议；每条建议 MUST 说明 provider/model、时间范围、样本数、比较依据和置信度。系统 MUST NOT 因建议自动切换模型、供应商或修改用户配置。

#### Scenario: 生成成本建议

- **WHEN** 至少两个候选组合达到最低样本阈值且单请求成本差异达到设定的最小比较幅度
- **THEN** 面板给出低成本建议并显示成本差异、样本数和时间范围

#### Scenario: 样本不足时不作最佳建议

- **WHEN** 候选组合的样本数低于最低阈值
- **THEN** 系统不把该组合标记为成本最佳、效率最佳或缓存最佳

#### Scenario: 建议不改变配置

- **WHEN** 面板生成或刷新一条建议
- **THEN** 系统只返回可解释文本与证据，不发起模型切换、不写入供应商配置

### Requirement: 保持统计口径一致

系统 SHALL 让洞察中的费用、tokens、请求数和项目归因与同一时间范围的总览及统计明细一致；洞察缺失不得阻断基础统计面板。

#### Scenario: 洞察与总览一致

- **WHEN** 用户查看同一时间范围的总览、排行和项目归因
- **THEN** 各区域的总费用、tokens 与请求数相互一致

#### Scenario: 洞察计算失败

- **WHEN** 真实延迟或建议计算失败但基础 usage 聚合成功
- **THEN** 面板保留基础总览和统计，并将受影响洞察显示为不可用状态
