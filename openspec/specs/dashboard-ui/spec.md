# dashboard-ui Specification

## Purpose

通过仅监听本机回环地址的 Web 服务与系统默认浏览器 UI 提供可视化监控面板，展示供应商状态、使用量统计和趋势图表，支持用户交互、自动轮询刷新，以及由 `on` / `off` 控制的进程级常驻生命周期。

## Requirements

### Requirement: 通过命令打开监控面板

系统 SHALL 提供 `/xpi-kuma` 命令，执行后启动或复用仅监听本机回环地址的监控 Web 服务，并使用系统默认浏览器打开监控面板。

#### Scenario: 成功打开面板

- **WHEN** 用户在已初始化的 Pi 会话中执行 `/xpi-kuma` 命令
- **THEN** 系统启动或复用本机监控 Web 服务（默认端口 `5180`，被占用时回退到由系统分配的临时端口并提示实际端口），并使用系统默认浏览器打开带有持久访问凭据的本机 URL

#### Scenario: 浏览器无法自动打开

- **WHEN** Web 服务已成功启动，但系统默认浏览器无法自动打开
- **THEN** 系统保持服务运行，并通过 Pi 通知显示可复制的本机访问 URL

#### Scenario: 重复执行命令

- **WHEN** 用户在同一个 Pi 进程中重复执行 `/xpi-kuma` 命令
- **THEN** 系统复用已有 Web 服务和访问凭据，不创建重复监听器，并再次打开或显示同一面板 URL

#### Scenario: 无配置供应商时提示

- **WHEN** 用户执行 `/xpi-kuma` 但配置文件中无任何供应商
- **THEN** 浏览器面板显示提示信息："未配置任何供应商，请编辑 ~/.pi/agent/data/xpi-kuma/config.yaml"

### Requirement: 供应商卡片网格展示

系统 SHALL 在面板顶部以网格布局展示所有配置供应商的卡片，每个卡片包含：
- 状态图标（🟢 正常 / 🔴 异常 / ⚪ 未知）
- 供应商名称和模型
- 配置的价格（每千 tokens）
- 最近一次 TTFT
- 最近一次总响应时间
- "刷新"按钮（触发单次立即探测）

#### Scenario: 显示供应商卡片

- **WHEN** 配置了3个供应商（OpenAI、Anthropic、9router），数据库中有各自的最新探测记录
- **THEN** 面板显示3个卡片，每个卡片显示对应供应商的状态图标、名称、价格和性能指标

#### Scenario: 点击刷新按钮

- **WHEN** 用户点击 OpenAI 卡片上的"刷新"按钮
- **THEN** 系统立即对 OpenAI 执行一次探测，完成后更新卡片上的状态和性能数据

### Requirement: 使用量统计展示

系统 SHALL 在使用量统计标签页展示按 provider/model 分组的真实使用量，并提供按费用、tokens、请求数排序的消费排行；排行 SHALL 展示费用占比、单请求成本和可计算的缓存命中率，默认限制首屏数量并将其余组合汇总或折叠。

统计区域包含：
- 时间范围选择器（1小时 / 24小时 / 7天 / 30天）
- 按供应商和模型分组的统计表格，每行按以下列序展示：
  - 供应商
  - 模型
  - 请求次数
  - 输入 tokens 数量与费用
  - 输出 tokens 数量与费用
  - 缓存读取 tokens 数量与费用
  - 缓存写入 tokens 数量与费用
  - 工具调用次数
  - 单请求成本
  - 缓存命中率
  - tokens 占比
  - 费用占比

#### Scenario: 显示消费排行

- **WHEN** 用户选择任一时间范围且存在多个 provider/model 组合
- **THEN** 统计区域显示按费用排序的主要组合，并为每行提供费用、费用占比、tokens、请求数和单请求成本

#### Scenario: 显示24小时统计

- **WHEN** 用户选择"24小时"时间范围且数据库中有相关记录
- **THEN** 统计表格显示所有 provider-model 组合的24小时聚合数据

#### Scenario: 切换时间范围

- **WHEN** 用户从"24小时"切换到"7天"
- **THEN** 统计表格、消费排行和趋势图表更新为最近7天的数据

#### Scenario: 空数据时显示

- **WHEN** 用户选择一个没有记录的时间范围
- **THEN** 统计表格显示暂无数据或等价空态，而不是误导性的非零行

#### Scenario: 小样本组合

- **WHEN** 某 provider/model 组合只有少量请求
- **THEN** 该组合仍可出现在基础统计中，但不得仅凭少量数据进入最佳效率或解释型建议

### Requirement: 趋势图表展示

系统 SHALL 在统计表格下方展示费用和 token 使用量的趋势折线图，支持：
- 横轴为时间（根据选择的时间范围自动调整粒度）
- 纵轴为费用（左轴）或 token 数量（右轴）
- 多条折线对比不同供应商

趋势图 SHALL 由页面自身渲染，MUST NOT 依赖任何外部脚本、样式或字体来源。

#### Scenario: 显示7天费用趋势

- **WHEN** 用户选择"7天"时间范围
- **THEN** 图表显示最近7天每天的费用曲线，每个供应商一条不同颜色的折线

#### Scenario: 图表交互

- **WHEN** 用户鼠标悬停在图表上某个数据点
- **THEN** 显示该数据点的详细信息（时间、供应商、具体费用）

#### Scenario: 零外部请求

- **WHEN** 面板页面在离线环境下加载
- **THEN** 趋势图正常渲染，页面不向任何外部域发起请求

#### Scenario: 图表无障碍

- **WHEN** 屏幕阅读器读取趋势图区域
- **THEN** 图表带有说明其含义的可访问名称，且数据点不依赖颜色单一通道传达

### Requirement: 实时数据更新

系统 SHALL 支持面板数据的手动刷新和自动轮询刷新；探测完成或新的使用量记录写入后，面板 SHALL 在下一次成功刷新时展示最新数据，且同一页面不得并发发起重复的自动刷新请求。该刷新行为 SHALL 在全部面板页面上保持一致。

#### Scenario: 手动刷新全部数据

- **WHEN** 用户点击面板上的"全部刷新"按钮
- **THEN** 系统对所有配置供应商执行探测，并重新查询使用量统计，更新面板所有区域

#### Scenario: 后台数据更新

- **WHEN** Pi 会话中的新 LLM 调用触发 `message_end` 并成功记录使用量，且面板页面处于可见状态
- **THEN** 面板在不超过5秒的下一次成功轮询后包含该新记录

#### Scenario: 页面不可见时暂停轮询

- **WHEN** 面板所在浏览器标签页进入不可见状态
- **THEN** 系统暂停自动轮询，并在页面恢复可见后立即执行一次刷新再恢复轮询

#### Scenario: 自动刷新失败

- **WHEN** 自动刷新请求因服务关闭或临时错误失败
- **THEN** 面板显示可理解的连接错误，保留当前已渲染数据，且不产生无界重试或并发请求

#### Scenario: 非主面板页面同样自动刷新

- **WHEN** 用户停留在账户页或配置体检页
- **THEN** 该页按其自身数据范围执行同样的轮询与失败处理，行为与主面板一致

### Requirement: 响应式布局

系统 SHALL 确保面板在不同浏览器视口尺寸下保持可用性，供应商卡片自动换行，表格可横向滚动，图表自适应可用宽度。该要求 SHALL 适用于全部面板页面。

#### Scenario: 小窗口时卡片自动换行

- **WHEN** 浏览器视口宽度小于800px 且有4个供应商卡片
- **THEN** 卡片网格减少列数并保持每个卡片内容可读，统计表格不会撑破页面布局

#### Scenario: 宽表格横向滚动

- **WHEN** 账户明细表或供应商体检表的列宽超过可用宽度
- **THEN** 表格自身横向滚动，不撑破页面整体布局

### Requirement: 遵循 DESIGN.md 设计规范

系统 SHALL 遵循项目 DESIGN.md 中定义的设计 token，包括：
- 配色使用 `oklch` 格式定义的颜色变量
- 默认「图鉴」家族 · 亮色主题
- 主题家族用下拉选择（默认 / 图鉴），暗色/亮色是独立按钮
- 字体使用 system-ui 无衬线字体
- 间距遵循 8px 基准网格

配色 SHALL 取自项目 `THEMES.md` 定义的主题家族，MUST NOT 为状态自造语义色。

#### Scenario: 图鉴亮色默认

- **WHEN** 用户首次打开监控面板且没有保存过偏好
- **THEN** 面板以图鉴家族、亮色模式渲染，且在首帧绘制前生效
#### Scenario: 主题切换

- **WHEN** 用户点击面板右上角的主题切换按钮
- **THEN** 面板从暗色主题切换到亮色主题（或反之），所有颜色 token 更新

#### Scenario: 数字与路径使用等宽字体

- **WHEN** 页面展示金额、token 数量或文件路径
- **THEN** 这些内容使用等宽字体与等宽数字，列与列之间保持对齐

#### Scenario: 状态不新增语义色

- **WHEN** 页面需要表达供应商正常、异常或未知
- **THEN** 只使用主题家族已有的前景色、破坏色与弱化前景色，不引入新的语义色

### Requirement: 本机服务访问控制

系统 MUST 仅在 IPv4 回环地址 `127.0.0.1` 上监听端口，MUST 默认使用配置项 `dashboard.port`（缺省 `5180`）并在该端口被占用时回退到由系统分配的临时端口，且 MUST 使用持久化在 `~/.pi/agent/data/xpi-kuma/dashboard.json`（权限 `0600`）的高熵随机访问凭据保护所有返回监控数据或触发探测的接口。系统 MUST NOT 将供应商 API Key、访问凭据或其他密钥写入日志、页面正文或错误响应。

#### Scenario: 非本机连接不可达

- **WHEN** 远端主机尝试通过设备的局域网地址访问监控端口
- **THEN** 连接不可达，因为服务没有监听非回环网络接口

#### Scenario: 未授权数据请求

- **WHEN** 请求未携带当前服务的有效访问凭据，或请求的 Host 与当前监听地址不匹配
- **THEN** 系统拒绝请求且不返回任何监控数据

#### Scenario: 未授权探测请求

- **WHEN** 请求尝试触发单个或全部供应商探测，但缺少有效访问凭据或来自不匹配的 Origin
- **THEN** 系统拒绝请求且不向任何供应商发送探测

#### Scenario: 浏览器地址不泄露密钥

- **WHEN** 系统构造并打开监控面板 URL
- **THEN** 访问凭据不得出现在会发送到 HTTP 服务、访问日志或第三方资源 Referer 的 URL 查询参数中

#### Scenario: 页面外壳不含数据

- **WHEN** 请求主面板、账户页、配置体检页或零数据引导态
- **THEN** 服务只返回不含任何监控数据与凭据的静态外壳，数据一律由页内脚本另行请求

#### Scenario: 页面链接携带凭据

- **WHEN** 用户从主面板进入账户页或配置体检页
- **THEN** 目标地址通过 URL fragment 携带本次服务凭据，该凭据不出现在发送到服务的请求中

#### Scenario: 新增写操作同样受控

- **WHEN** 请求触发余额同步、OAuth 授权或手动余额写入
- **THEN** 系统要求有效凭据且校验请求 Origin 与当前服务一致，否则拒绝且不产生任何副作用

#### Scenario: 目标端口被占用

- **WHEN** 配置的目标端口已被其他进程占用
- **THEN** 系统回退到由系统分配的临时端口继续启动，并通过 Pi 通知告知实际使用的端口，不因端口冲突而失败

#### Scenario: 凭据跨启动复用与轮换

- **WHEN** 服务重启（重新执行 `/xpi-kuma`）或用户删除凭据文件后再次启动
- **THEN** 前者沿用同一凭据，旧书签继续可用；后者生成新凭据，旧凭据失效

#### Scenario: 页面不加载外部资源

- **WHEN** 任意面板页面被浏览器加载
- **THEN** 其内容安全策略不允许任何外部脚本、样式或字体来源

### Requirement: Web 服务生命周期

系统 SHALL 将监控 Web 服务绑定到当前 Pi 进程的生命周期并跨会话常驻，SHALL 在 `/xpi-kuma off`（或 Pi 退出）时停止接受新请求、取消后续页面刷新能力并释放监听端口，且 MUST NOT 在会话关闭时关闭服务。

#### Scenario: 会话切换不释放服务

- **WHEN** Pi 触发 `session_shutdown`，包括退出、reload、新建、恢复或 fork 会话
- **THEN** 监控 Web 服务继续监听，原浏览器页面的请求仍然成功

#### Scenario: off 关闭不阻塞 Pi

- **WHEN** 用户执行 `/xpi-kuma off` 且浏览器仍保持页面打开
- **THEN** 系统在有限时间内完成服务关闭，不等待浏览器主动断开

#### Scenario: off 后 on 重新启动

- **WHEN** 用户执行 `/xpi-kuma off` 之后再次执行 `/xpi-kuma on`
- **THEN** 系统在同一端口以同一持久凭据重新启动服务，旧 URL 继续可用

### Requirement: 多页面导航

系统 SHALL 提供主面板、零数据引导态、供应商账户、配置体检四个页面，各自拥有独立地址；每个页面 SHALL 提供回到主面板的入口，主面板 SHALL 提供进入账户页与体检页的入口。

#### Scenario: 独立地址访问

- **WHEN** 用户在已打开的浏览器中访问账户页地址
- **THEN** 系统返回该页面的完整内容，其主题、语言与访问凭据沿用同一服务

#### Scenario: 页头互链

- **WHEN** 用户位于账户页或配置体检页
- **THEN** 页头提供"返回主面板"入口，点击后回到主面板

#### Scenario: 主面板入口

- **WHEN** 用户位于主面板
- **THEN** 供应商总览标签页头部同时提供"账户详情"与"配置体检"两个入口

#### Scenario: 偏好跨页一致

- **WHEN** 用户在任一页面切换主题、主题家族或语言后进入另一页面
- **THEN** 新页面沿用同一偏好，且首帧即应用，不出现闪烁

### Requirement: 使用量总览展示

系统 SHALL 在使用量总览标签页展示本期用量，包含本周期花费、token 总量、请求次数、覆盖项目数和可计算的缓存命中率，并随所选时间范围刷新。总览 SHALL 提供消费结构、provider/model 消费排行、项目费用排行、效率排行和解释型建议的入口或区域。效率与建议无数据时 MUST 保留基础总览并显示明确空态。面板视觉 SHALL 采用 shadcn base 组件规范的 CSS 移植：只用仓库既有 CSS token 实现，MUST NOT 引入 React、构建步骤或任何外部资源。

#### Scenario: 展示扩展后的概览

- **WHEN** 用户打开主面板且所选时间范围内有使用量记录
- **THEN** 标签页显示本期花费、token 总量、请求次数、覆盖项目数、缓存命中率，以及消费排行和项目费用排行

#### Scenario: 展示四项概览

- **WHEN** 用户打开主面板且所选时间范围内有使用量记录
- **THEN** 标签页显示本期花费、token 总量、请求次数与覆盖项目数，数值与使用量统计一致

#### Scenario: 展示效率与建议

- **WHEN** 时间范围内存在满足样本阈值的真实调用延迟数据
- **THEN** 总览显示效率排行和带样本数、时间范围、依据与置信度的只读建议

#### Scenario: 效率数据不可用

- **WHEN** 时间范围内没有可靠真实调用延迟或样本不足
- **THEN** 总览保留基础统计，并将效率排行和建议标记为暂无数据或样本不足，不使用 probe 或估算值替代

#### Scenario: 切换时间范围刷新概览

- **WHEN** 用户从"24小时"切换到"7天"
- **THEN** 所有概览、排行、项目归因、效率和建议均按新范围重新计算

#### Scenario: 无记录时

- **WHEN** 所选时间范围内没有任何使用量记录
- **THEN** 概览显示零值或暂无数据，并引导用户查看产生数据的路径

### Requirement: 标签页导航

系统 SHALL 把主面板的四个区块（使用量总览、使用量统计、趋势、供应商总览）组织为标签页，一次只显示一个面板，并且只用键盘也能完成切换。

#### Scenario: 切换标签页

- **WHEN** 用户点击某个标签，或聚焦标签后按左右方向键 / Home / End
- **THEN** 对应面板显示，其余面板隐藏，且任一时刻只有一个标签的 aria-selected 为 true

#### Scenario: 刷新不重置标签页

- **WHEN** 轮询或手动刷新返回新数据
- **THEN** 当前选中的标签页保持不变

### Requirement: 零数据引导态

系统 SHALL 在首次运行、无使用量记录或未配置供应商时提供独立的零数据引导页，说明产生数据的三条路径，并提供返回主面板的入口。

#### Scenario: 未配置供应商

- **WHEN** 用户打开面板但配置文件中没有任何供应商
- **THEN** 引导页提示编辑全局配置 `~/.pi/agent/data/xpi-kuma/config.yaml` 添加供应商

#### Scenario: 有供应商但无记录

- **WHEN** 已配置供应商但数据库中没有使用量记录
- **THEN** 引导页列出产生数据的三条路径，并说明数据出现后主面板会自动展示

#### Scenario: 返回主面板

- **WHEN** 用户在引导页点击返回
- **THEN** 系统回到主面板

### Requirement: 主题家族与语言切换

系统 SHALL 支持在 `THEMES.md` 定义的主题家族之间切换，并 SHALL 支持中文与英文两种界面语言；偏好 SHALL 持久化在浏览器本地，并在页面首帧渲染前应用。

#### Scenario: 切换主题家族

- **WHEN** 用户在主面板点击主题家族切换
- **THEN** 全部页面改用另一套家族的颜色与形状 token，且刷新后保持

#### Scenario: 切换语言

- **WHEN** 用户切换界面语言
- **THEN** 页面文案在中文与英文之间切换，且刷新后保持

#### Scenario: 首帧不闪烁

- **WHEN** 用户在已选择偏好后重新打开任一页面
- **THEN** 页面在首次绘制前即应用已保存的主题家族与语言，不出现默认外观闪现

#### Scenario: 家族专属装饰按家族显示
