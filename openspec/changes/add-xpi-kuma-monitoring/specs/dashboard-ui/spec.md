## Purpose

通过 Glimpse 原生窗口提供可视化监控面板，展示供应商状态、使用量统计和趋势图表，支持用户交互和实时刷新。

## ADDED Requirements

### Requirement: 通过命令打开监控面板

系统 SHALL 提供 `/xpi-kuma` 命令，执行后打开 Glimpse 原生窗口，展示监控面板。

#### Scenario: 成功打开面板

- **WHEN** 用户在 Pi 中执行 `/xpi-kuma` 命令
- **THEN** 系统打开一个 Glimpse 原生窗口，标题为 "xpi-kuma 监控面板"，尺寸为 1200x800

#### Scenario: 无配置供应商时提示

- **WHEN** 用户执行 `/xpi-kuma` 但配置文件中无任何供应商
- **THEN** 面板显示提示信息："未配置任何供应商，请编辑 .pi/xpi-kuma/config.yaml"

### Requirement: 供应商卡片网格展示

系统 SHALL 在面板顶部以网格布局展示所有配置供应商的卡片，每个卡片包含：
- 状态图标（🟢 正常 / 🔴 异常 / ⚪ 未知）
- 供应商名称和模型
- 配置的价格（每千 tokens）
- 最近一次 TTFT
- 最近一次总响应时间
- "刷新"按钮（触发单次立即探测）

#### Scenario: 显示供应商卡片

- **WHEN** 配置了3个供应商（OpenAI、Anthropic、9router），数据库中有各自的最新探测记录
- **THEN** 面板显示3个卡片，每个卡片显示对应供应商的状态图标、名称、价格和性能指标

#### Scenario: 点击刷新按钮

- **WHEN** 用户点击 OpenAI 卡片上的"刷新"按钮
- **THEN** 系统立即对 OpenAI 执行一次探测，完成后更新卡片上的状态和性能数据

### Requirement: 使用量统计展示

系统 SHALL 在供应商卡片下方展示使用量统计区域，包含：
- 时间范围选择器（1小时 / 24小时 / 7天 / 30天）
- 按供应商和模型分组的统计表格，每行包含：
  - 供应商名称和模型
  - 输入 tokens 数量和费用
  - 输出 tokens 数量和费用
  - 缓存读取 tokens 数量和费用
  - 缓存写入 tokens 数量和费用
  - 总费用
  - 请求次数

#### Scenario: 显示24小时统计

- **WHEN** 用户选择"24小时"时间范围且数据库中有相关记录
- **THEN** 统计表格显示所有供应商-模型组合的24小时内的聚合数据

#### Scenario: 切换时间范围

- **WHEN** 用户从"24小时"切换到"7天"
- **THEN** 面板重新查询数据库，更新统计表格和趋势图表为最近7天的数据

#### Scenario: 空数据时显示

- **WHEN** 用户选择"1小时"时间范围但数据库中无该时段记录
- **THEN** 统计表格显示"暂无数据"或零值行

### Requirement: 趋势图表展示

系统 SHALL 在统计表格下方展示费用和 token 使用量的趋势折线图，支持：
- 横轴为时间（根据选择的时间范围自动调整粒度）
- 纵轴为费用（左轴）或 token 数量（右轴）
- 多条折线对比不同供应商

#### Scenario: 显示7天费用趋势

- **WHEN** 用户选择"7天"时间范围
- **THEN** 图表显示最近7天每天的费用曲线，每个供应商一条不同颜色的折线

#### Scenario: 图表交互

- **WHEN** 用户鼠标悬停在图表上某个数据点
- **THEN** 显示该数据点的详细信息（时间、供应商、具体费用）

### Requirement: 实时数据更新

系统 SHALL 支持面板数据的手动刷新和自动刷新，当探测完成或新的使用量记录时，面板可更新展示最新数据。

#### Scenario: 手动刷新全部数据

- **WHEN** 用户点击面板上的"全部刷新"按钮
- **THEN** 系统对所有配置供应商执行探测，并重新查询使用量统计，更新面板所有区域

#### Scenario: 后台数据更新

- **WHEN** Pi 会话中有新的 LLM 调用完成，触发 `message_end` 事件记录使用量
- **THEN** 如果监控面板当前打开，统计数据在下次刷新时包含该新记录（不要求实时推送，仅在用户刷新时更新）

### Requirement: 响应式布局

系统 SHALL 确保面板在不同窗口尺寸下保持可用性，供应商卡片自动换行，表格和图表自适应宽度。

#### Scenario: 小窗口时卡片自动换行

- **WHEN** Glimpse 窗口宽度小于 800px 且有4个供应商卡片
- **THEN** 卡片网格从3列自动调整为2列，保持每个卡片内容可读

### Requirement: 遵循 DESIGN.md 设计规范

系统 SHALL 遵循项目 DESIGN.md 中定义的设计 token，包括：
- 配色使用 `oklch` 格式定义的颜色变量
- 默认暗色主题
- 支持暗色/亮色主题切换按钮
- 字体使用 system-ui 无衬线字体
- 间距遵循 8px 基准网格

#### Scenario: 暗色主题默认

- **WHEN** 用户首次打开监控面板
- **THEN** 面板使用暗色主题（背景 `oklch(0.15 0.02 240)`，前景 `oklch(0.95 0.02 240)`）

#### Scenario: 主题切换

- **WHEN** 用户点击面板右上角的主题切换按钮
- **THEN** 面板从暗色主题切换到亮色主题（或反之），所有颜色 token 更新
