## Why

当前网页和供应商探测只能随 Pi 进程运行，无法通过终端独立启动并在 Pi 退出后继续监控。更严重的是，Pi 扩展的 `off` 会销毁整个运行时，导致 Pi 仍在运行时后续真实用量不再写入；扩展缺席期间的用量虽保存在 Pi 会话日志，却没有幂等补录机制。

## What Changes

- 增加全局终端命令 `xpi-kuma on --port <port>`、`xpi-kuma off` 和运行状态查询，后台服务脱离启动终端运行。
- 独立服务拥有网页端口和供应商定时探测；Pi 扩展检测到独立服务后让出端口和探测，但始终负责记录实时用量。
- 将 Pi 内真实用量记录生命周期与网页/探测服务开关解耦，`off` 不停止会话中的用量采集。
- 在 Pi 会话启动和独立服务启动时，从 Pi 持久会话日志幂等补录尚未进入数据库的真实用量，包括扩展或服务缺席期间的记录；无法核实的条目显式报告。
- 保持本机回环监听、既有访问凭据、配置和数据库位置；后台子进程不得继承宿主终端输出。

## Capabilities

### New Capabilities
- `standalone-service`: 全局命令、脱离终端的服务生命周期、端口/探测所有权与 Pi 扩展协作。

### Modified Capabilities
- `usage-collection`: 实时采集独立于服务 on/off，并在 Pi 会话启动时从会话日志补齐缺失的真实用量，保证重扫幂等。
- `dashboard-ui`: Pi 内命令在独立服务拥有网页时复用其入口，更新原有 Pi 进程内 Web 生命周期的例外。
- `vendor-monitoring`: 探测所有权改为 Pi 内服务或独立服务单方持有，不再无条件跟随 session_start 启停。

## Impact

- 影响 `src/index.ts` 的运行时生命周期与命令处理、`src/ui/dashboard.ts` 的服务启动参数、SQLite usage schema/迁移、Pi 会话日志读取，以及新增的命令行入口和相关测试。
- 共享目录位于 `~/.pi/agent/data/xpi-kuma/`；进程协调需要原子状态/锁文件，且必须遵循 `PI_CODING_AGENT_DIR` 的覆盖路径。
- 不引入新的运行时依赖或打包步骤；终端分离遵循仓库 stderr 纪律。
- 真实调用延迟无法从历史日志推断，补录记录对应延迟字段保持未知。
